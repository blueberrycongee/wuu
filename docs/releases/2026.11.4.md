## Compatibility and migration

Existing model selections and explicit connection settings are preserved; retained model metadata does not guarantee continued availability from the provider. The new file APIs and plugin-family metadata are optional additions to the existing Extension API. Extensions using file saving or observation must check the host's advertised capabilities.

This release removes the experimental Project Agent, including `project.coordination@1`, the `project_session` tool, desktop `application.projects`, project draft mode, project work methods on `session.domain@1`, and the legacy `thread/control/take` and `thread/control/return` RPCs. Ordinary workspace projects and `host.managed-session@1` remain available. Extensions using the removed contracts must remove those dependencies and composition selections before upgrading; there is no replacement project scheduler. The verified pre-removal host and repository SDK reference is `e1de6e0ca` (SDK `0.1.0`), with PR #1167 marking the removal boundary. The unchanged SDK package number does not identify support.

Historical Project Agent conversations remain readable in the regular session list, but cannot run or resume queued work. Work records are preserved during storage migration, and old `project_models` and `project_max_parallel` settings are ignored. Start a new ordinary conversation to continue work. Keep the previous executable and a consistent backup of history, bindings, checkpoints, and configuration before upgrading; reverting requires both, and cannot undo external effects that already occurred. See the [compatibility guide](https://github.com/blueberrycongee/wuu/blob/v2026.11.4/docs/en/customize/plugin-compatibility.md) for details.
