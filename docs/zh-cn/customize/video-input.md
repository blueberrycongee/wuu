# 视频输入

在桌面会话输入框中，可以通过粘贴、拖放或文件选择添加 MP4、MOV、WebM 视频。附件可显示名称、时长和大小；本机编解码器支持时，还可以直接播放。

每次发送的视频总量最多 **20 MiB**。Wuu 使用有限大小的内联数据，不会自动转码、提取帧、分块上传，也不会通过服务商 Files API 上传大视频。模型能否理解音轨，取决于具体模型。

## 选择兼容的模型和连接

视频输入同时要求模型支持和请求格式兼容。成功登录、模型支持图片或服务提供视频生成，都不足以证明可以输入视频。

| 连接 | Wuu 当前的接入规则 |
|---|---|
| OpenRouter Chat | 模型目录声明视频输入时，使用 `video_url` 发送 |
| DashScope / Model Studio Chat | 模型声明支持时，使用相同视频格式 |
| 自定义 Chat 兼容服务 | 可以明确声明 `options.video_input: "video_url"` |
| OpenAI Responses，包括复用 Codex 登录 | 拒绝新增视频输入 |
| SuperGrok OAuth、Grok Build、Anthropic Messages | 适配器关闭视频输入 |
| Gemini 直接兼容端点 | 不自动开启；Wuu 未集成 Gemini 原生视频 API |

新增附件不受支持时，会报错并要求选择兼容模型和连接。后续切换到不支持的模型，历史附件仍会保留，但在该次请求上下文中表示为不可读取的视频。

## 为自定义模型声明支持

在已有服务配置的模型条目中加入以下字段，并替换为实际模型 ID：

```json
{
  "models": {
    "your-model-id": {
      "modalities": { "input": ["text", "image", "video"], "output": ["text"] },
      "options": { "video_input": "video_url" }
    }
  }
}
```

端点必须确实能通过 Chat 接收内联 `video_url` 内容。`video_input` 是 Wuu 的接入选项，不会作为服务请求参数发送。它不能覆盖模型明确不支持视频的声明，也不能开启适配器禁用的视频能力。

## 视频失败时

先检查总大小、文件格式、所选模型和连接协议。本地可播放、接入检查通过，都不证明服务商能分析视频。账户和下游路由可能还有时长、格式和访问限制。依赖结果之前，先用简短、不敏感的视频验证。
