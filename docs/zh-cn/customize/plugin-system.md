# 插件架构

Wuu 通过 Go 运行时宿主和 Electron 桌面宿主加载插件。一个包可以使用其中一个或两个宿主，也可以只提供声明式贡献。本页说明当前实现如何发现、激活、组合和清理这些贡献；包字段和代码示例见[编写插件](plugin-authoring.md)。

## 宿主和插件的职责

Go 宿主负责工具分派、执行身份、服务路由、会话持久化、权限和资源清理。插件负责功能逻辑、提示词、业务状态和后台策略。自动化、记忆、子 Agent 等功能通过宿主服务工作，而不是另外维护一套会话引擎。

桌面宿主负责窗口、布局、会话消息流、输入提交，以及通向 Go app-server 的桥接。插件通过公开 SDK 注册视图和贡献，不会获得 Electron 主进程对象，也不能直接访问宿主 React 状态。宿主提供 React 和共享 UI 组件，让插件控件遵循相同的渲染与样式契约。

内置包和外部包使用相同的运行时与桌面注册契约。内置来源影响发现和信任，不会改变工具、能力或 UI 注册的含义。复制一个包并使用内置插件的 ID，不会让它成为官方包。

## 发现和激活

发现流程依次读取用户包、工作区包、已授权开发目录和内置包。用户包通常位于 `$WUU_HOME/plugins`，工作区包位于工作区的 `.wuu/plugins`，同时兼容旧的单数 `plugin` 目录。ID 重复时，后发现的候选覆盖之前的候选；内置包最后参与发现。

发现 manifest 不等于执行插件。宿主还会检查启用状态、信任、平台与最低版本兼容性、包关系，以及运行时协商结果。缺少 `requires` 依赖会让消费者保持未激活；`breaks` 和依赖环可能拒绝整个激活计划。`conflicts` 只产生诊断，不自动决定保留哪一方。

当前本地安装器先暂存包或更新，再单独确认信任。开发授权只适用于特定目录。包身份包含内容和来源上下文，因此仅凭 ID 或版本字符串，无法证明当前执行的就是已批准的字节。实际安装和更新流程见[插件管理](plugins.md)。

## 运行时 generation

运行时 generation 是一组一起生效的插件资源，包括所选包、进程、工具、能力、hook、技能、MCP 连接、服务注册表和受管包快照。构建候选 generation 不会立即替换活动版本。

预检查期间，进程初始化并描述自身契约，只能访问读取阶段的宿主服务。插件应在 `activate` 中启动定时器等活动行为，而不是在 `initialize` 中启动。宿主检查候选后，才将它绑定到会话。

激活会在事务锁内切换工作区的当前插件绑定。如果候选激活失败，就关闭候选；如果重新绑定后的持久化提交失败，则恢复当前绑定并关闭候选。成功发布后，之后新建的会话使用新 generation。已经开始的会话继续使用它钉住的 generation，直到该会话重建；旧 generation 只在这些会话释放后才清理。此后的清理错误会被报告，不会回滚已经成功的替换。

清理会关闭 MCP 连接、移除提示词和压缩注册、取消插件执行、关闭进程、撤销服务路由，并删除受管快照。关闭路由前，shutdown 仍可访问释放插件工作所需的宿主服务。插件仍须自行停止定时器、订阅和后台任务；宿主无法推断扩展代码创建的任意资源。

清理过程产生结构化撤销记录，保存在 Wuu 主目录的 `plugin-generation-revocations.jsonl` 中。记录将发布成功与旧资源清理失败分开，便于定位未正常关闭的资源。

## 服务与执行

运行时插件使用 JSONL 通信。版本化服务统一通过 `host.service.call` 调用：provider 声明名称、版本和方法，消费者声明服务名与主版本。注册表将消费者绑定到 provider，并提供调用者身份。缺少必需 provider 时，消费者无法正常启用；同名同主版本的多个 provider 会产生诊断，不会合并实现。

核心服务覆盖存储、设置、会话、历史、工作区、产物和执行操作。功能服务也使用相同的路由机制。服务方法的 schema 标识描述其契约，不授予直接调用其他插件私有进程或读取私有存储的权限。

工具和能力分派会创建有明确边界的执行作用域，进度、子工具调用、提问和产物都附属于活动执行。取消会关闭作用域，不等待插件确认，迟到的更新也不能重新激活它。插件收到中止信号后，应将其传递给可取消的操作。服务注册表关闭时拒绝新工作，等待已有调用结束，并在关闭上下文到期时取消剩余调用。

能力在指定位置参与组合，例如添加提示上下文或观察轮次完成，不是对 agent 循环或 provider 请求的任意拦截。支持的能力和错误策略见[编写插件](plugin-authoring.md)。

## 桌面 generation 与组合

桌面宿主加载符合条件的包的 ESM 入口，调用 `activate(api)`。注册归属于该包的 generation。宿主先验证声明的贡献和视图目标，再发布候选并清理旧桌面 generation。候选注册失败时，只清理候选，不替换已有的桌面 generation。

这个桌面事务与 Go 运行时事务分开。不能假设包安装、运行时激活和所有 renderer 窗口具有统一的原子回滚。应根据失败位置查看运行时或桌面诊断。

不同 UI 扩展点承担不同职责：

| 扩展点 | 用途 |
| --- | --- |
| View 与放置规则 | 在宿主管理的布局区域中显示插件内容 |
| Slot | 在固定插入点添加小型贡献 |
| Surface | 替换或包装受支持的较大 UI 区域 |
| Presenter | 渲染版本化语义快照，调用宿主管理的动作 |
| 主题与限定作用域的样式 | 在公开 token 和样式契约内调整外观 |

Presenter 接收快照，不获得可修改的宿主 store。即使动作被列为可用，调用时仍会检查当前可写状态和参数。错误边界与默认渲染可在受支持区域隔离普通贡献错误，但不是防范恶意代码的安全沙箱。目标和组合规则见[桌面 UI 插件](desktop-plugins.md)。

## 信任、恢复与兼容性

插件是以用户权限运行的受信代码。manifest 权限和服务声明描述契约，不会隔离进程与机器。工具权限检查和文件系统进程约束分别保护对应的宿主执行路径，不会把任意插件代码变成可安全运行的不受信代码。

禁用插件会让之后新建的会话不再加载其贡献。已经开始的会话继续使用它钉住的 generation，直到该会话重建。通常保留存储和设置，也不会撤销已经完成的外部操作。安全模式和默认 UI 恢复用于扩展失败后的恢复。Wuu 不审计或认证第三方包，详见[安全模型](../reference/security-model.md)。

兼容性分为多个独立层面：产品 CalVer、包 schema、运行时能力协议、服务主版本和桌面快照版本。应使用与目标宿主匹配的 SDK。当前 `wuu plugin dev` 构建包含 manifest 的包目录，不会直接加载任意 TypeScript 文件。构建、包验证、运行时协商测试，以及实际功能或 UI 检查，分别验证这条路径的不同部分。
