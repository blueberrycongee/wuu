# 记忆

Memory 插件保存会话结束后仍然有用的信息。用户笔记本适合偏好和可复用的反馈，工作区记忆适合长期项目知识。会话历史和核心 agent 的工作笔记是另外两类记录。

## 用户笔记本

在**扩展**中启用 Memory，再从**设置 → 扩展**打开它的设置页。你可以查看笔记本源文件、生成概览，或让记忆管理会话添加、修正、删除信息。管理会话会报告修改了哪些文件；需要确认准确结果时，应直接检查这些文件。

笔记本位于 Wuu 主目录下的 `memory/`，默认是 `~/.wuu/memory/`。`MEMORY.md` 是索引，各个 Markdown 文件保存具体记忆。保存或忘记一个主题，需要同时修改主题文件和索引条目。插件提供 `memory_list`、`memory_read`、`memory_write` 和 `memory_delete` 工具完成这些操作。

插件会把有限长度的索引放入 agent 上下文，帮助它找到相关主题，而不是每次请求都加载所有主题文件。概览由模型生成，可能过时；源文件才是实际保存内容的依据。查看源文件不需要模型请求，生成概览和通过会话管理记忆则需要。

## 工作区记忆

插件的 `session_memory` 工具通过 `project_memory` 保存单个工作区的稳定知识。内容位于该工作区状态目录下的 `memory/MEMORY.md`，与用户笔记本分开。agent 按需读取，并可追加或替换内容。

适合保存的内容包括已经确认的架构决策、反复适用的工作经验，以及难以重新发现的工具限制。团队共享规则优先放在仓库指令中；源码里很容易查到的事实，直接查源码即可。

## 会话状态

Memory 还通过 `session_memory` 提供 `summary`、`checkpoint` 和 `notes` 目标。这些是插件管理的会话文件，其中 `checkpoint` 用于兼容。

核心 `notes` 工具与此不同。它为当前会话维护持久的虚拟工作笔记，可记录目标、约束、进展和检查结果。这些笔记在上下文重置、重启和切换模型后仍保留，不写入项目文件，也不依赖 Memory 插件。两种会话笔记都不等同于跨项目的用户记忆。

## 保持记忆有用

只保存已经确认、长期有效的信息。不要把记忆当作会话归档、密钥存储或临时任务日志。记忆与当前证据冲突时，应修正记忆，而不是盲目遵循。

记忆可能发送给已配置的模型，并影响后续操作。请检查敏感条目和导入的不可信文本。禁用插件会移除它的提示、工具和设置页，但不会删除已有笔记本文件。

[Dream](dream.md) 可以在后台整理工作区知识，需要单独开启，也会产生额外模型请求。`AGENTS.md` 等项目指令独立于这两个插件；相关说明见[配置](../reference/configuration.md)和[安全模型](../reference/security-model.md)。
