# 完成第一个任务

选一个不含敏感资料、可以恢复的小项目，先阅读，再改动，最后检查结果。

## 先阅读项目

在左侧栏的**工作区**区域选择**添加工作区 → 使用现有文件夹**。第一次建议使用：

- 一个可以重新克隆的代码仓库；
- 一个专门准备的测试文件夹；
- 或通过**新建空白项目**创建的目录。

工作区是文件和命令的主要边界。会话也按工作区组织；如果看到错误的文件或历史会话，
先检查当前选择的工作区。

## 先让 wuu 阅读

发送前可以用输入框旁的权限按钮选择**只读**。权限模式只控制 Wuu 的工具边界，不会把
项目放进操作系统沙箱；普通修改任务保持**标准**即可。**替我审批**是标准模式的选项，
会在执行前审查高风险工具调用，但不会扩大工作区边界。

在目标工作区中新建对话，先发送一个只读任务：
在左侧栏选择**添加工作区 → 使用现有文件夹**，或用**新建空白项目**准备测试目录。
确认当前工作区，在其中新建对话。发送前用输入框旁的权限菜单选择**只读**：

```text
先阅读这个工作区，不要修改文件。说明它的用途、主要目录，以及可以怎样验证它。
```

核对回答中的目录和测试命令。如果读错了项目，停止当前任务，重新选择工作区。

只读模式拒绝文件修改；命令工具还会应用文件系统沙箱。网络和继承的环境变量仍需留意，
处理不可信代码应使用独立隔离环境，见[权限模式](../reference/permissions.md)。

## 做一个小改动

切换到**标准**模式，说明期望结果、修改范围和验证方法。例如：

```text
修复当前失败的测试。只修改与失败原因有关的代码，不做无关重构。完成后运行相关测试，
并告诉我修改了哪些文件、测试结果是什么。
```

较大的功能可以先要求调查和计划，确认后再实施。对话中会显示读取、编辑和命令执行等
工具活动；方向偏了就停止，补充约束后继续。

## 检查并继续

在输入框中使用这些命令打开检查工具：

| 命令 | 用途 |
|---|---|
| `/files` | 浏览和打开项目文件 |
| `/diff` | 查看 Git 改动，检查范围、无关修改和敏感信息 |
| `/terminal` | 打开工作区 shell，自己运行检查 |

核对最终回答和实际输出，确认测试或构建确实运行并通过，再决定是否提交或发布。
需要修正时直接回复；稍后可从侧栏重新打开同一个对话继续。

输入框支持图片、PDF 和 MP4、WebM、MOV 视频，实际处理能力取决于所选服务商和模型。
附件不会自动成为项目文件，需要保留到工作区时请说明目标路径。

更多操作见[文件、改动与终端](../desktop/workspace-tools.md)和[会话](../desktop/conversations.md)。
从 CLI 执行和恢复任务见 [`wuu exec` 指南](../automation/exec.md)。
