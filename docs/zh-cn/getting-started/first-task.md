# 完成第一个任务

选一个可以恢复的小项目，例如 Git 仓库的临时副本。这个练习先让 Agent 解释项目，再做一处修改，最后检查结果。

## 选择文件夹

在侧栏选择**添加工作区 → 使用现有文件夹**，选中项目目录。如果想从空目录开始，选择**新建空白工作区**。在这个工作区中打开对话，发送前确认目录无误。

添加工作区不会复制文件夹，Agent 操作的就是真实文件。请先保存或提交需要保留的已有改动。

## 先做只读调查

使用内置 Wuu 引擎时，在输入框旁的权限菜单中选择**只读**，然后发送：

```text
先阅读这个工作区，不要修改文件。说明它的用途、主要目录，以及可以怎样验证它。
```

核对回答涉及的文件是否属于预期工作区。如果目录不对，停止任务，选好工作区后再继续。

只读模式会阻止文件编辑，并用文件系统沙箱限制命令写入。它不会隔离网络访问和继承的环境变量。如果无法提供所需沙箱，命令会失败，不会自动改为无约束执行。完整规则及外部引擎的差异见[权限模式](../reference/permissions.md)。

## 做一个小改动

准备允许修改时，选择**标准**。给出范围明确、结果可检查的任务，例如：

```text
修复搜索结果为空时失败的测试。只处理这个问题，运行相关测试并报告命令和结果。
暂时不要提交。
```

请把示例换成项目中真实存在的问题。较大的功能可以先要求调查和计划。执行中如果需要调整范围，可以停止任务并补充说明，但停止不会撤销已经产生的改动。

## 检查结果

可以从输入框打开检查工具：

| 命令 | 用途 |
|---|---|
| `/files` | 浏览和打开工作区文件 |
| `/diff` | 查看当前 Git 改动 |
| `/terminal` | 在工作区 shell 中自行验证 |

确认 diff 中只有预期修改，报告的测试命令也确实执行成功。如果检查未能运行，先决定是修复环境还是换一种方式验证，再考虑提交或发布。

你在终端中输入的命令使用自己的操作系统权限，不受 Agent 的只读设置限制。不要仅为了绕过 Agent 的权限错误，就把命令粘贴到终端运行。

需要修正时，直接在当前对话回复；稍后也可以从侧栏重新打开。想尝试另一种方案，可以[分叉对话](../desktop/conversations.md)。文件预览和交付文件的用法见[工作区工具](../desktop/workspace-tools.md)。

## 发送与停止

处理计时从点击发送开始，包含等待本地请求被接收的时间。状态更新和切换会话不会重置计时；答案就绪或执行结束时计时冻结。重新打开历史、没有本地发送记录时，使用服务端执行耗时。

新会话创建期间也可以继续发送消息进入队列，第一条请求被接收后会按序提交。创建失败或取消时，输入保留为草稿；若生成了恢复草稿，可通过提示打开。

点击停止后，原按钮显示进度图案，直到执行结束。仍在等待提交的消息会保留，不会自动启动。如果 Wuu 无法确认停止，按钮提供重试，不会显示成已停止；输入框里的草稿也会保留。
