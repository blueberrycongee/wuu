# 快速开始

这条路径帮助你从零开始，在桌面端完成第一个真实任务。完成后，你会拥有一个已经连接
模型服务的 wuu、一个本地工作区，以及一段可以继续使用的会话。

## 你需要准备

- 一台 Apple 芯片 Mac。当前 GitHub Release 提供未签名的 macOS arm64 预览版。
- 一个受支持模型服务的 API Key。OpenAI OAuth 当前需要已有 Wuu 凭据，或先通过
  Codex CLI 登录并在配置中允许复用该凭据，桌面端暂不能直接发起 OAuth 登录。
- 一个你愿意让 wuu 读取和修改的本地文件夹。第一次尝试可以使用测试项目或新建空白
  文件夹，不要直接选择包含敏感资料的目录。

## 第一步：安装 wuu

从 GitHub Releases 下载桌面应用，放入 `/Applications` 并完成首次启动。当前预览版
未签名；如果 macOS 阻止打开，需要先确认下载来源，再移除 quarantine 标记。

[查看完整安装步骤](installation.md)

## 第二步：连接模型服务

打开 wuu 的**设置 → 模型服务**，添加一个模型服务并设为当前服务。你需要选择服务
类型、填写模型名称，并根据服务要求提供 API Key 和端点。

[查看模型服务配置](model-services.md)

## 第三步：添加工作区

在左侧栏找到**工作区**，选择**添加工作区 → 使用现有文件夹**，然后选择准备好的
目录。工作区决定 wuu 可以直接操作哪些文件，也决定会话在侧边栏中的归属。

wuu 还提供不绑定用户项目目录的共享“对话”区域。它使用 Wuu 管理的持久 scratch
工作区，也能创建文件和打开终端；但所有无项目会话共用该目录。需要操作现有项目、
检查 Git 改动或明确管理成果位置时，应选择真实文件夹。

## 第四步：完成第一个任务

在工作区中新建对话。第一次建议先让 wuu 阅读，不要立即修改：

```text
先阅读这个工作区，不要修改文件。告诉我它包含什么，以及应该怎样验证现有内容。
```

确认 wuu 识别了正确目录后，再交给它一个范围明确、可以验证的任务：

```text
检查这个项目当前的测试，修复失败项。完成后运行相关测试，并总结修改了哪些文件。
```

运行过程中可以查看工具活动；完成后用 `/files` 浏览文件、用 `/diff` 检查 Git 改动，
或者用 `/terminal` 打开当前工作区的终端。输入 `/` 可以查看当前版本实际提供的命令，
不必记住完整列表。

[了解怎样交代和检查第一个任务](first-task.md)

## 第五步：继续工作

wuu 会保存会话。你可以在左侧栏重新打开它，继续补充要求或让 wuu 修正结果，不必在
每条消息里重新解释整个项目。

需要提供工作区外的图片或 PDF 时，可以把它们作为附件加入当前消息。附件只让当前任务
能够读取对应内容，不会自动把原文件复制进工作区。

## CLI 快速路径

桌面应用和 CLI 可以独立安装。产品版本使用日期版本，日期标签不是 Go 模块主版本；只需要自动化入口时，从源码工作树构建并初始化 CLI：

```bash
git clone https://github.com/blueberrycongee/wuu.git
cd wuu
make install
wuu init
cd path/to/project
wuu exec "描述一下这个工作区"
```

常用参数、会话恢复和 JSONL 输出见[中文 `wuu exec` 指南](../automation/exec.md)；完整
输入对象参考见[英文文档](../../en/automation/exec.md)。

## 使用前应知道

- wuu 可以修改本地文件并运行命令；发送任务前确认当前工作区和权限模式。
- 提示词及相关上下文会发送给你配置的模型服务。模型在该服务的基础设施上运行。
- 不要把 API Key 写进项目文件或提交到 Git。
- 对不可信仓库或敏感资料操作前，先阅读[安全模型](../reference/security-model.md)。

下一步可以阅读[桌面工作区](../desktop/workspaces.md)，或者阅读[权限模式](../reference/permissions.md)
了解每个任务能访问和修改什么。
