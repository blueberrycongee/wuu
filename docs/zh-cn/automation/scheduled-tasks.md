# 自动化

自动化按时间发送任务提示，适合定期项目检查、摘要或一次性跟进。Automation 插件必须启用，Wuu 也必须在未休眠的机器上运行；这不是云端托管调度器。

## 创建任务

1. 打开**自动化**并选择工作区。这会选择任务项目，不会切换当前对话。
2. 选择**新建自动化**，或从建议开始，填写名称和清晰的任务内容。
3. 在**运行于**中选择每次新建会话，或选择已有会话。
4. 设置每天、工作日、每周或自定义时间。**更多设置**包含时区、仅执行一次和独立运行。
5. 选择**创建**。之后的编辑需要点击**保存修改**。

提示中除了目标，也应写明限制：

```text
汇总这个项目主分支自昨天以来的变更。如果能取得检查结果，指出失败项。
不要修改文件，也不要发布任何内容。
```

## 选择执行位置

新会话任务每次创建一个可见会话，各次运行可以重叠。开启独立运行后，会基于项目当前 `HEAD` 创建单独的 Git worktree，不复制尚未提交的改动。

已有会话任务继续使用该会话的上下文和工作区。如果会话正忙，消息会排在当前工作之后。这种模式不能创建新的 worktree。agent 的 `cron` 工具把两种模式称为 `new_thread` 和 `thread_heartbeat`。

## 时间与错过的触发

自定义时间使用五字段 cron 表达式。`0 9 * * 1-5` 表示所选时区工作日的 09:00。时区采用 `Asia/Shanghai` 等 IANA 名称，桌面最初选择系统时区。

插件约每 15 秒检查一次到期任务，因此不能保证精确到秒启动。停机后恢复时，过期的一次性任务会派发一次；过期的重复任务也只派发一次，再从当前时间计算下一次，而不是逐次补跑所有错过的时间。

一次性任务在派发时就会离开计划，即使后续执行失败也一样。应查看运行记录确认结果；它不会自动作为新的单次任务重试。

## 管理与查看结果

暂停和继续控制未来触发。删除只移除计划，不删除已经创建的会话，也不会停止正在运行的工作；需要到对应会话中停止。关闭编辑器或选择其他任务会丢弃未保存的修改。

详情面板显示最近运行和错误。「已完成」筛选显示仍保留记录的成功单次任务快照；重复任务成功运行一次，不代表计划结束。每个工作区最多保留 100 个任务和 500 条运行记录。

没有看到运行时，先确认 Wuu 当时未休眠且正在运行、插件已启用、任务未暂停，以及工作区和目标会话仍存在，再检查时区、下次运行时间和错误。模型访问权限、额度、网络和执行权限都可能导致失败。

CI 或 Wuu 之外的调度器可以使用 [`wuu exec`](exec.md)。
