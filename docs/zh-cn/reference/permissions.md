# 权限模式

权限模式控制 Agent 能访问和修改哪些本地路径。桌面端可以在输入框旁的运行时菜单中
切换；CLI 可以使用 `wuu exec --permission-mode` 覆盖单次运行。

## 三种模式

| 模式 | 适合场景 | 行为 |
|---|---|---|
| 标准 `standard` | 日常项目任务 | 读写当前 runtime 注册的文件根，包括 Agent home、用户工作区和系统临时目录，并保留敏感路径和高风险操作防护 |
| 只读 `read_only` | 理解代码、调查和评审 | 保持相同读取范围，但拒绝文件修改 |
| 无限制 `unconfined` | 明确需要访问工作区外文件的可信任务 | 移除 Wuu 的路径边界，允许访问和修改当前系统用户有权操作的内容 |

没有明确理由时使用标准模式。只需要分析时使用只读。`unconfined` 应视为把当前登录
用户级别的本机权限交给 Agent，只对可信任务短时启用。

## 替我审批

桌面端权限菜单里的**替我审批**是标准模式的一个选项，只对内置 Wuu 引擎生效。它
不是第四种权限模式，也不会扩大工作区边界。

开启后，高风险的原生工具调用（shell、Git、进程、浏览器、MCP，以及其他破坏性或
高风险工具）会在执行前经过审查。工作区内的普通只读操作仍走原来的允许路径。审查
可以放行这次调用、拒绝它，或让主 Agent 在对话里说明具体动作，并等待用户对这个
目标给出知情同意。超时或审查失败不是安全判定：动作不会执行，Agent 也不得绕过
检查。

替我审批不能把会话切到无限制、读写 Wuu 凭据文件，或通过专用文件工具写入已知敏
感路径。`wuu exec` 不提供这个选项；非交互运行仍然只有允许或拒绝。

即使在 `unconfined` 下，专用工具仍保留以下纵深防护：

- `.env`、SSH 私钥、凭据配置等已知敏感路径不能通过专用文件工具写入，也不能通过
  结构化 Git 工具暂存或提交；
- `~/.wuu`（或 `WUU_HOME`）下的应用凭据文件（`auth.json`、`credentials.json`、
  `remote.json`、`phone.json`）不能通过这些专用工具直接读写；
- 命令输出中的常见密钥格式始终脱敏。

这些是特定工具的保护，不是对所有执行路径的承诺。任意 shell 命令、脚本和子进程会继承
Wuu 进程的系统权限，可能绕过上述文件和 Git 限制；输出脱敏也不能识别所有密钥或间接
泄露路径。因此，“凭据不可访问”或“敏感文件不可提交”不能当作系统级安全保证。

## 系统权限与隔离

获准运行的子进程会继承 Wuu 的系统身份、环境变量和网络能力。Wuu 权限模式不是操作系统
沙箱。处理恶意仓库、依赖或原生程序时，应使用 macOS 沙箱、容器、虚拟机或独立系统账号
建立真正的安全边界。

## CLI 示例

```bash
wuu exec --permission-mode read_only "解释这个仓库，不要修改文件"
wuu exec --permission-mode standard "修复测试并验证"
```

`wuu exec` 是非交互式入口，权限判断只有允许或拒绝，不会在脚本中弹出等待确认的对话框。

## 配置所有权

正常启动时，项目配置不能替换用户选择的权限模式。这样可以避免打开仓库时被项目文件
静默扩大本地权限。完整加载顺序见[配置模型](configuration.md)，更详细的风险边界见
[安全模型](security-model.md)。
