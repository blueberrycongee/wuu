# 安全模型

Wuu 是一个本地 Coding Agent。它会读取项目上下文，把选定的上下文发送给模型提供商，
也可以在用户的机器上运行工具。这些能力带来了实际权限，因此在 Wuu 中打开的仓库更应
被视为可执行代码，而不是被动文档。

本文说明 Wuu 当前的安全边界。模型输出仍需检查；处理不可信代码时，应使用容器、虚拟机或
独立系统账号进一步隔离。

## 权限模式

Wuu 提供三种权限模式（`standard` / `read_only` / `unconfined`），控制 Agent 能
访问和修改哪些本地路径；日常切换方式和 CLI 覆盖见[权限模式](permissions.md)。

`standard` 和 `read_only` 下，Wuu 的命令工具会应用文件系统沙箱，限制文件写入；
具体范围和后端要求见[权限模式](permissions.md#系统权限与隔离)。进程仍保留系统身份、
继承的环境变量和网络访问，这层保护不能保证凭据保密。`unconfined` 移除这层沙箱和路径边界，
把当前登录用户级别的本机权限交给 Agent，只应对
可信任务短时启用；专用文件与 Git 工具保留的敏感路径防护（`.env`、SSH 私钥、
`~/.wuu` 凭据文件等）属于纵深防御，任意 shell 命令、脚本和子进程仍可能绕过。
在 `standard` 和 `read_only` 模式下，暴露完整环境、读取常见凭据路径、执行不安全
Git 操作或修改软件包和网络状态的命令，还会受到额外的风险分类或强制检查，工具输出
对常见密钥格式脱敏。

处理不信任的仓库时，请使用一次性虚拟机、容器或独立的操作系统账户。不要用权限模式
代替完整的运行环境隔离。

## 发送给模型提供商的数据

根据任务和启用的功能，Wuu 可能向已配置的模型提供商发送：

- 用户消息和对话历史；
- 系统提示词及适用的指令文件；
- 文件内容、搜索结果、diff、命令输出和工具错误；
- 已启用 Memory 插件选择的用户、工作区或会话记忆；
- 用户添加的图片或其他附件；
- 返回给 Agent 的 MCP 或 hook 输出。

Wuu 不会有意把提供商 API Key 放进提示词。如果命令、hook、MCP 服务器、文件或用户
消息以未被识别的形式输出密钥，密钥仍可能泄露。请查看所选提供商的隐私与数据保留
条款。自定义 OpenAI 兼容地址会收到与其所替代提供商相同的提示词数据。

## 可信配置与项目输入

`~/.wuu/config.json`（或 `WUU_HOME/config.json`）中的用户配置是信任基础。正常
启动时，Wuu 会阻止项目替换提供商地址、凭据环境变量名、工作区外指令路径、模型角色
或权限模式。`wuu exec --config` 和 `--ignore-user-config` 会显式信任所选项目配置，
适用于受控的自动化环境。

以下项目内容会影响 Agent 行为，使用前应检查：

- `AGENTS.md` 和其他自动发现的指令文件；
- `.wuu.json`、`wuu.json`、`.wuu/settings.json` 和本地设置；
- 项目 skills 和追加的提示词；
- hooks 和插件；
- `.mcp.json` 和原生 MCP 服务器配置。

项目 MCP 配置只有在本地设置中获准后才会加载。批准意味着信任该服务器或子进程访问
它能够获得的文件、环境变量、网络和凭据；MCP 输出本身也属于不可信的模型输入。即使
hook 和本地 skill 不执行原生代码，其中仍可能包含提示词注入。

## 凭据与本地状态

- 提供商密钥通常从 `providers.<name>.api_key_env` 指定的环境变量读取。
- macOS 桌面端把托管的 OAuth 凭据保存在钥匙串中；如果钥匙串失败，不会静默回退到
  明文文件。
- 无界面流程可以显式使用 `~/.wuu/auth.json` 和 `~/.wuu/credentials.json`（或
  对应的 `WUU_HOME` 路径）。Wuu 会把凭据文件设置为仅所有者可读写，但这不能替代
  操作系统钥匙串。
- 远程身份和已注册设备的数据保存在 `~/.wuu/remote.json`；手机凭据保存在
  `~/.wuu/phone.json`。这些文件同样仅限所有者访问，备份和分享时应按密钥处理。
- 会话、日志、工具结果、记忆和工作区状态保存在 `~/.wuu`。即使常见凭据格式已被
  脱敏，其中仍可能包含源代码和对话内容。

把 `~/.wuu`、环境文件、日志、会话导出或诊断包加入问题报告前，请先检查其中的内容。

## App server 与桌面端边界

`wuu app-server` 通过子进程的标准输入和标准输出使用逐行 JSON 请求/响应协议，本身不会打开网络
监听端口。Electron 客户端负责启动并管理该进程，通过 preload/IPC 桥向 renderer
开放选定操作。任何从 renderer 绕过 IPC 限制的方式或不安全的页面跳转都属于安全
问题。

## 远程与手机控制

`wuu relay` 默认监听 `127.0.0.1:8787`。绑定到其他地址会把服务暴露给对应网络，
此时操作者必须根据部署环境提供 TLS 和相应的安全控制。

远程主机会主动连接 relay，不会开放入站工作区服务器。手机通过限时配对链接注册。
已注册设备使用签名密钥认证，应用数据帧在主机与手机之间端到端加密。relay 只转发
不透明的数据帧和不含内容的推送提示，但仍能看到连接时间、设备在线状态、配对标识符
和网络地址。获得有效配对链接或手机凭据文件的人，可能以该设备身份注册或操作。

应把已配对手机视为拥有主机会话同等工作区权限的远程控制器。设备丢失或不再可信时，
请撤销其权限。

## 安全使用检查清单

1. 为新仓库启用工具前，检查其中的指令、设置、hooks、skills 和 MCP 配置。
2. 检查代码时使用 `read_only`；处理恶意代码时使用独立隔离环境。
3. 把提供商地址和凭据环境变量名保存在用户配置中。
4. 私下完成远程设备配对；relay 跨越不可信网络时使用 `wss://`。
5. 发布改动前检查 diff 和命令输出。
6. 按照 [SECURITY.md](../../../SECURITY.md) 的说明私下报告边界绕过问题。
