# 隔离的用户宿主

用户宿主在整个生命周期内绑定一个用户空间和产品域。Personal Agent 使用这个宿主，不借用项目工作区。现有 Coding 宿主保留原有配置、工具和连接生命周期。

## 启用前提

Personal 的生产启用默认拒绝。在创建私有状态或启动模型服务之前，内部应用嵌入层必须提供可信的 `UserHostIsolationVerifier`。它是宿主集成，不能由客户端自行声明。当前命令行入口没有提供这个验证器，会返回 `user_host_isolation_required`。

独立目录、环境变量或同一用户身份下的独立进程都不足以证明隔离。拥有不受限工具的 Coding 进程若使用相同操作系统身份，仍可能读取 Personal 文件。部署必须双向执行边界，例如使用独立隔离的宿主身份，或具有等效保证且经过验证的沙箱。只收紧 Personal 的工具策略不能证明这个边界。不要通过关闭正常 Coding 能力来假装满足前提。

`app-server` 和 `remote host` 接受 `--user-space`、`--product-domain`，用于标识请求的宿主。这两个参数不启用隔离。用户宿主不能继承工作区身份，也不能借用 Coding 桌面的执行桥接。远程宿主会先检查隔离，再加载或创建远程身份。模型访问、连接器授权、设备配对、通知凭据和部署仍需分别配置。

## 身份和存储

绑定由宿主提供，并通过 `initialize` 的 `user_space_id` 和 `product_domain` 返回。客户端调用 Personal 服务前应核验绑定。扩展清单变化不会改变绑定。

在 Wuu 数据目录中，用户数据分为：

- `user-spaces/<user-space>/<domain>/state`：Session、私有插件存储、记忆和托管附件
- `user-spaces/<user-space>/<domain>/files`：允许访问的工作文件和用户明确提交的附件工作副本

用户宿主加载明确的绝对路径配置或用户配置，不继承项目指令、Coding 全局技能、MCP、hooks 或外部执行环境。Personal 文件及进程工具不能访问受保护的私有状态路径。已安装扩展仍属于可信代码；这不是不可信扩展沙箱。

每个具名 Agent 绑定一个持久主 Session。客户端按 Agent ID 导航，不展示后台执行会话选择器。事项有独立执行 Session 和需求版本。主 Session 缺失时明确报告恢复错误，不静默重建。

## 常驻执行和连接生命周期

内部 SDK 为每个用户运行时创建一个 `UserHost` 执行权威，在客户端连接前完成 Session 路由绑定。多个已认证连接共用这个权威；关闭连接或发送协议 `shutdown` 仅断开该客户端。已接受的工作可以在没有客户端连接时继续。

连接内 RPC ID 和取消操作彼此隔离。业务请求 ID 保持不变，以便重连重试恢复同一持久回执。EOF 撤销仍在运行的前台提交权限，即使回调派生了脱离取消的上下文也不能延长权限；已经接受的执行不会因此撤销。

慢客户端使用有界队列，超限后断开，不阻塞其他连接或后台完成。宿主最多支持 16 个同时连接的客户端传输。应用所有者需先取消或关闭传输、等待 `Serve` 返回，再调用 SDK `Runtime.Close`。关闭执行权威会结束其后台执行，与关闭窗口不同。

用户宿主传输仅开放 `initialize`、`plugin/client/request`、`plugin/client/cancel`、用户问题决策接口、设备绑定的推送注册和连接关闭。通用 Coding thread、workspace、storage、配置及包修改接口不可用。桌面扩展管理仍使用正常宿主上下文。Coding 账号历史导出器发现用户宿主绑定后停止，不导出 Personal 数据，也不把其清单当作 Coding 删除记录。

非交互远程宿主不提供通用 `ask_user` 交互。Calendar 不可变操作预览等插件专属确认契约，是独立的客户端操作。

持久化的所有者通过 `session.attention` 按当前通知和安静时段设置决定是否提醒。原始执行结束事件不能授权 Personal 推送。`Runtime.SubscribeUserAttention` 是独立于手机连接的宿主级观察器；有界、无正文的启动缓冲在重放前重新检查当前归属、代际和策略。它提供尽力通知，不是持久化的提供方送达回执。关闭或停用所有者会阻止迟到提醒。

通知聚合默认关闭。设置窗口（最长 15 分钟）后，分别按负责助理合并待提醒事件，以第一条准入事件的固定截止时间发送。每条对话结果仍即时保留。宿主最多保留 128 组内存队列及最新消息定位；退出可能丢失这些尽力通知。发送及远程重放前重新检查最新条目的当前策略；最新定位失效时保守地取消整组提醒。手机收到一条通用的助理通知，不是逐项精确摘要。改为零会影响新的准入事件；已有窗口通常保留原截止时间。

Personal 历史搜索使用可见对话投影，分页前应用可选的 RFC3339 时间范围：包含 `time_min`，不包含 `time_max`。搜索可见的用户和助理文字，不搜索隐藏推理或执行工具记录。结果序号定位到原主对话消息；旧记录缺少时间时保持未知。Coding 原有执行历史检索不变。

## 前台输入和附件

客户端在宿主管理的 `user_input` 信封内提交准确的用户输入。插件方法参数只携带附件引用，不能提供文件路径或替换字节。准入会绑定插件、原始文本、业务请求 ID、附件顺序、文件名、媒体类型和 SHA-256 摘要，并且只能授权绑定的发送。后台回调不能伪造用户权限。

宿主每次最多接受 16 个附件，解码后总计 20 MiB。Personal 文本最多 64,000 个 UTF-8 字节。原生客户端保留较小的传输限制。只有选择附件时才允许空文本。

历史只暴露附件元数据，不暴露本地路径或内联文件字节。`host.session.attachment.read` 从有归属的持久记录中读取有界 base64 分片；偏移量以 base64 字符计数。Personal 提供按 Agent 和事项限定的适配器。客户端展示预览或下载前核验元数据和最终摘要。原生及桌面渲染不会自动加载模型提供的远程图片或任意本地 URL。

## 业务契约和外部服务

Personal Agent 共享带来源归属和版本化纠正的 Personal Memory 服务。遗忘会清除记忆记录正文，阻止它参与后续综合；不表示源对话、用户文件和备份也已删除。Coding 记忆保持独立。

事项完成需核验持久化的成功执行证据。负责 Agent 的结果投递单独记录为等待、已提交、已送达或失败；事项完成本身不表示主对话里已经出现结果回复。这些检查能证明归属和状态转换，不能证明外部结果本身正确。暂停和停止会持久化取消意图，涵盖后代工作和已排队结果；执行宿主暂不可用时，恢复可能仍处于等待状态。

内置 Calendar 适配器初始未连接。读写接口可接入可信的、绑定用户空间和账号的现有授权提供方；工具参数和插件配置不能传入凭据。默认运行时尚未绑定授权提供方或写入器，嵌入应用需在单独完成账号授权后提供集成，源码适配器测试不能代替这一步。写入契约要求展示完整不可变预览、用户明确确认、准确版本和摘要，以及写后读取核验。确认回执丢失会进入结果不确定状态，通过对账恢复，不盲目重复写入。注入式提供方测试不等于真实 OAuth 或账号结果验证。
