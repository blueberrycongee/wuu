# 会话与分支

会话将消息、工具活动和结果保存在一起。同一项工作的后续要求可以继续在原会话中提出；无关任务适合新建对话，尝试其他思路则可以从较早消息分叉。

## 快捷访问与独立对话窗口

在**设置 → 常规 → 快捷访问**中录制全局组合键，或选择**使用默认快捷键**（macOS 为 Command + Shift + Space，其他系统为 Ctrl + Shift + Space）。初始未设置快捷键，Wuu 需保持运行。快捷键会恢复并聚焦上次使用的主窗口或独立对话窗口，保留其中的对话和未发送草稿，不会发送消息。如果该窗口已关闭，则打开或聚焦主窗口。

如果组合键已被占用或当前桌面无法注册，请选择其他组合键；原来可用的快捷键保持生效。**停用**会释放快捷键。**独立对话窗口置顶**应用于当前和之后打开的所有独立对话窗口。这些偏好会在重启后保留。

## 新建和整理会话

先选择工作区，再新建对话。点击会话标题栏中的标题即可重命名。已有会话会立即保存；新建对话会在首条消息创建会话时沿用这个名称。侧栏菜单仍提供重命名、置顶和归档。归档会从普通列表中隐藏会话，之后可以在**设置 → 归档**中恢复。

删除不可恢复：它会移除保存的历史，清理关联产物，以及仍绑定到该会话的 worktree。删除前请保留需要的成果和改动。会话、侧聊或子代理仍在运行时，Wuu 会拒绝删除。

首条消息发送后，工作区侧栏会立即显示正在创建的会话；创建期间可以切换离开再回来。点击停止可取消等待并保留输入。即使创建结果稍后才返回，也不会发送已取消的消息或保留未使用的空会话。再新建对话会使用独立草稿。

## 查找对话

点击侧栏的**搜索对话**，或按 **Command + P**（Windows 和 Linux 上为 **Ctrl + P**）。未输入关键词时，先显示置顶对话，再按最近更新时间显示其他对话。输入后会跨项目搜索标题和历史内容，包括已归档对话。每条结果显示所属项目；内容命中时，在同一行组内显示带匹配词强调的片段。其他信息相同的结果还会显示最后更新的日期和时间。

使用方向键和 Enter，或直接点击结果。带消息地址的用户和助手消息命中会展开并高亮对应消息，包括较早轮次。长消息会加载完整内容并滚动到匹配文本；标题、元数据和工具记录命中会正常打开对话。打开归档结果不会将它恢复到侧栏。按 Escape 关闭搜索，焦点回到打开搜索前的控件。

## 选择新对话的工作位置

新对话输入框上方的项目控件显示它所属的工作区。在 Git 项目中，旁边的第二个控件包含分支和**工作树**开关：

| 工作树 | 选择分支时 |
|---|---|
| 关闭 | 在项目中检出该分支。你的编辑器、终端和项目里的其他会话都会看到这次切换。 |
| 开启 | 只设置新 worktree 的起始分支，项目保持在当前分支。 |

开启**工作树**后，首条消息会用所选分支的已提交内容创建一个独立目录，会话在其中工作。项目中未提交的改动不会带入。worktree 创建时没有自己的分支（分离 `HEAD`），要从它创建拉取请求，需要先建立具名分支。开关只作用于一个新对话，之后的草稿会重新在项目中开始。

## 任务运行时

输入框支持以下键盘操作：

| 按键 | 操作 |
|---|---|
| Enter | 发送草稿；引擎支持引导运行中的任务时，将消息补充到当前任务 |
| Command + Enter（Windows 和 Linux 上为 Ctrl + Enter） | 当前支持排队且草稿非空时，留到本轮结束后处理 |
| Shift + Enter | 换行 |
| Escape | 输入框允许中断时，停止运行中的任务 |

`/` 菜单打开时，Enter 和 Tab 用于选择命令。其余情况下 Tab 保持普通焦点切换。发送控件会反映当前引擎是支持即时引导，还是只能排队。

最终答复完成后，按 Enter 或点击发送会开启正常的下一轮对话，分屏中也一样。后台收尾、已加载会话的后台刷新不会阻止发送。即使在附件准备期间切换页面，消息仍发往提交时的会话和工作区。

发送失败时，如果原输入框仍为空，Wuu 会恢复输入。如果已经切换会话或输入了新草稿，失败的内容会保留在原会话中；如果连会话创建都失败，错误提示会提供打开保留草稿或丢弃它的操作。失败内容不会自动重试。

点击停止可以中断任务，但不会撤销已经执行的命令或文件改动；独立管理的后台工作可能还需要单独停止。继续前先检查[当前 diff 和命令结果](workspace-tools.md#审查)。

## 引用答复中的一段文字

在助手答复中选中已显示的文字，即使答复仍在输出，也可以选择**添加到对话**；也可以先选择**批注**，在选中段落旁添加可选批注。只要选中文字仍然有效，后续追加输出和本轮完成都会保留选区与批注；选中段落改变时，菜单会关闭。选区会作为引用卡片出现在该会话输入框上方的附件栏中，分屏中也一样。每条引用保存的是选取时已显示的文字。打开卡片可以查看原文、修改批注、移除选区或定位来源。无需另写消息也可以直接发送选区；发送、排队和即时引导都会把引用原文及批注加入模型输入。

切换标签页或退出分屏时，已选文本片段会随草稿保留。发送失败或编辑保留的消息时，引用会单独恢复，不会把序列化上下文塞入输入框。原答复已经加载且可见时，**查看原文**会高亮准确的选中位置；原答复隐藏、未加载或已改变时，会提示不可用，而不是跳到另一处相同文字。请先打开原会话并加载对应答复，再重试。

旧版宿主可能丢弃引用元数据，但保留发送的文字；旧版桌面端可能不显示结构化引用。请搭配使用当前版本的宿主和桌面端，以便在编辑与历史恢复时保留结构化引用。原生客户端会以普通文字显示引用和批注。

## 附加粘贴的长文本

粘贴的长文本会作为 `.txt` 附件出现在输入框上方，与图片、文档和引用放在一起。已有指令保留在输入框中；如果粘贴时选中了文字，只移除该选区。点击卡片会将完整原文直接铺回输入框，方便编辑，之后按普通消息文本发送；保持附件状态时则按文件发送。移除一份附件不会影响其他附件和指令。短文本仍按普通文字粘贴。

发送时，Wuu 会在工作区状态目录下的 `sessions/<thread-id>/input-attachments/` 中生成 UTF-8 工作文件。模型收到文件引用，需要时通过文件工具读取内容，不再将整段粘贴原文直接放进上下文。会话历史保留包含原始空白的完整文本快照，用于预览、编辑和重新发送。

文本工作文件与图片工作文件一样，七天后过期。清理不会删除历史快照或已保存到缓存目录外的副本。打开历史不会重建过期文件；重新发送附件会生成新的工作副本。需要保留超过七天时，请把文件保存到工作区。

## 操作粘贴的图片

粘贴图片或选择图片文件后发送消息，Wuu 会保存一份本地工作文件，并将绝对路径与用于视觉理解的图片一同交给模型。你可以让模型通过普通文件和命令工具复制、移动或处理这个文件。工作文件保留后端收到的字节；桌面端发送前的图片压缩仍然适用。

上下文压缩省略图片数据时，图片说明和摘要输入的媒体索引会保留工作文件路径。压缩不会重建已丢失的文件，也不会延长文件的有效期。

工作文件位于工作区的 Wuu 状态目录下的 `sessions/<thread-id>/input-images/`，七天后过期。Wuu 会在 app-server 启动时及运行期间每六小时检查过期文件，因此实际删除可能晚于过期时间。清理不会移除会话历史中的图片，也不会删除已复制或移动到缓存目录外的文件。如需长期保留，可以让模型把图片保存到工作区；如果工作文件已经过期，请重新发送图片。

## 从较早消息分叉

在历史消息上选择**分叉**，再选择新会话在哪里工作：

| 选项 | 新会话使用的文件 |
|---|---|
| 派生到本地 | 与原会话相同的目录 |
| 派生到 Git worktree | 从源仓库当前 `HEAD` 创建的独立目录 |

分叉会复制到所选消息为止的对话历史，但**不会**把文件恢复到那一刻。worktree 从已提交内容开始，不复制未提交的改动；如需继承这些改动，应先检查并提交，再创建分叉。不能创建 worktree 时，对话框会说明原因。

## 询问旁支问题

使用 `/side` 可以询问进度、解释输出或比较方案，消息不会加入主对话。也可以在仍在输出或已完成的助手答复中选中文字，选择**在侧边聊天中提问**；侧聊输入框会显示相同的选区标签，发送问题时会附上原文作为来源上下文。是否可用取决于执行引擎。需要长期开展的另一项工作，更适合新建会话或分叉。

## 在 CLI 中使用已保存会话

```bash
wuu session list
wuu session show --last
wuu session search "关键词"
wuu exec resume THREAD_ID "继续这个任务"
```

`wuu exec --continue` 继续最近的会话；`--ephemeral` 运行时不保存会话。选择会话和脚本选项详见 [`wuu exec`](../automation/exec.md)。
