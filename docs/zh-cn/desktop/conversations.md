# 会话与分支

会话将消息、工具活动和结果保存在一起。同一项工作的后续要求可以继续在原会话中提出；无关任务适合新建对话，尝试其他思路则可以从较早消息分叉。

## 新建和整理会话

先选择工作区，再新建对话。点击会话标题栏中的标题即可重命名。已有会话会立即保存；新建对话会在首条消息创建会话时沿用这个名称。侧栏菜单仍提供重命名、置顶和归档。归档会从普通列表中隐藏会话，之后可以在**设置 → 归档**中恢复。

删除不可恢复：它会移除保存的历史，清理关联产物，以及仍绑定到该会话的分叉 worktree。删除前请保留需要的成果和改动。会话、侧聊或子代理仍在运行时，Wuu 会拒绝删除。

首条消息发送后，工作区侧栏会立即显示正在创建的会话；创建期间可以切换离开再回来。点击停止可取消等待并保留输入。即使创建结果稍后才返回，也不会发送已取消的消息或保留未使用的空会话。再新建对话会使用独立草稿。

## 任务运行时

输入框支持以下键盘操作：

| 按键 | 操作 |
|---|---|
| Enter | 发送草稿；引擎支持引导运行中的任务时，将消息补充到当前任务 |
| Command + Enter（Windows 和 Linux 上为 Ctrl + Enter） | 当前支持排队且草稿非空时，留到本轮结束后处理 |
| Shift + Enter | 换行 |
| Escape | 输入框允许中断时，停止运行中的任务 |

`/` 菜单打开时，Enter 和 Tab 用于选择命令。其余情况下 Tab 保持普通焦点切换。发送控件会反映当前引擎是支持即时引导，还是只能排队。

最终答复完成后，按 Enter 或点击发送会开启正常的下一轮对话，分屏中也一样。后台收尾、已加载会话的后台刷新不会阻止发送。即使在附件准备期间切换页面，消息仍发往提交时的会话和工作区。

发送失败时，如果原输入框仍为空，Wuu 会恢复输入。如果已经切换会话或输入了新草稿，失败的内容会保留在原会话中；如果连会话创建都失败，错误提示会提供打开保留草稿或丢弃它的操作。失败内容不会自动重试。

点击停止可以中断任务，但不会撤销已经执行的命令或文件改动；独立管理的后台工作可能还需要单独停止。继续前先检查[当前 diff 和命令结果](workspace-tools.md#审查)。

## 从较早消息分叉

在历史消息上选择**分叉**，再选择新会话在哪里工作：

| 选项 | 新会话使用的文件 |
|---|---|
| 派生到本地 | 与原会话相同的目录 |
| 派生到 Git worktree | 从源仓库当前 `HEAD` 创建的独立目录 |

分叉会复制到所选消息为止的对话历史，但**不会**把文件恢复到那一刻。worktree 从已提交内容开始，不复制未提交的改动；如需继承这些改动，应先检查并提交，再创建分叉。不能创建 worktree 时，对话框会说明原因。

## 询问旁支问题

使用 `/side` 可以询问进度、解释输出或比较方案，消息不会加入主对话。是否可用取决于执行引擎。需要长期开展的另一项工作，更适合新建会话或分叉。

## 在 CLI 中使用已保存会话

```bash
wuu session list
wuu session show --last
wuu session search "关键词"
wuu exec resume THREAD_ID "继续这个任务"
```

`wuu exec --continue` 继续最近的会话；`--ephemeral` 运行时不保存会话。选择会话和脚本选项详见 [`wuu exec`](../automation/exec.md)。
