# 项目

项目是一个与协调者的对话，用于在同一个工作区里推进较大的一块工作，例如一个功能、一次迁移或一轮清理。协调者负责规划，记住你的目标和决定，并把每一处改动交给它管理的会话去做。你审阅这些会话的产出，决定哪些进入工作区。

## 开始一个项目

项目在侧栏顶部有自己的分组。在**项目**分组里选择 **+**，在当前工作区开始一个项目；或者在工作区的菜单里选择**新建项目**，在那个工作区开始。随后会打开一个项目草稿；选择**新对话**可以把它变回对话草稿。

告诉协调者你要的结果和约束：

```text
把目录搜索改成服务端分页，每页 50 条。
保持公开 API 不变。
```

发送第一条消息时项目才会创建，名称取自这条消息的第一行，之后可以像对话一样重命名。一个工作区可以有多个项目。

协调者会读取工作区，包括 `AGENTS.md` 等指令（见[配置](../reference/configuration.md)）和技能，但不能改动任何东西。它可以读取和搜索文件、运行只读命令、使用网络；不能编辑文件、运行会改动内容的命令，也不能操作浏览器。小而独立的任务用普通对话更快，也更省 token。

## 会话负责干活

协调者为每一块独立的工作启动一个托管会话，并为它写一份任务说明。会话看不到项目对话，只看到自己的任务说明和后续指令。每个会话都是普通对话，你随时可以打开。

要把已有的工作带进项目，把对话从它的工作区拖到侧栏里的项目上。此后由协调者管理它，协调者会读到它最近的回答。只有同一个工作区的对话可以加入。

项目在侧栏里只占一行，它的会话不会挤进工作区列表。有会话在运行时，这一行会显示运行状态，还会显示有几份提案等你审阅。在项目对话里：

- 输入框上方显示项目正在运行的工作和待审数量，点击会在右栏打开项目：先是待审阅的内容，再是每个会话。你接管或暂停的会话会标明状态。
- 每个事件（例如某个会话完成了一轮）显示为一行，带**审阅**和**打开会话**；**详情**会显示协调者收到的原文。

在 Git 工作区中，会改动文件的会话默认在自己的 Git worktree 中工作，并行的会话不会互相覆盖。直接在工作区中工作的会话会原地修改文件。

会话的一个回合结束后，由协调者决定下一步：发出纠正、启动后续会话，或者告诉你哪些已经可以审阅。结果是证据，不代表目标已经达成。需要独立检查时，可以让协调者审查某个改动：它会从该改动的冻结副本启动一个单独的会话，审查可以运行测试，而不会修改这个改动。

## 审阅并应用改动

worktree 会话在一个回合结束时如果有改动，Wuu 会把它们冻结为一份提案：这个会话中所有还没有应用或发布的改动。同一会话的新提案会取代旧提案，所以每个会话始终只有一份待决定的提案。提案也会显示在产生它的那一轮下面。选择**审阅**，在右栏查看改动的文件和 diff，然后选择其一：

- **应用到工作区**：把改动写入工作区，不暂存。工作区有冲突改动时不会应用任何内容，提案保持待处理。
- **开 PR**：由扩展提供时出现，例如 [Git Delivery 示例](../../../examples/plugins/git-delivery/README.md)。开 PR 即是这份提案的决定，PR 链接会保留在提案上。
- **驳回**：记录你拒绝了这份改动。改动仍留在会话的 worktree 里；除非会话撤回，它们还会出现在下一份提案中。

协调者会得知你的选择。会话的下一份提案从你已应用或已发布的状态开始，已交付的改动不会再次出现。

## 给会话补充指令或接管会话

你随时可以在托管会话里发消息。消息会补充到正在进行的回合，或开始新的一轮；项目继续管理这个会话，协调者会连同这一轮的结果读到你写的内容。

要在没有协调者的情况下使用某个会话，在它的标题栏选择**接管**。停止一个回合也会同样暂停管理。在你选择**交还给项目**之前，协调者不会再给这个会话指令；交还后，协调者会先检查改动再继续。你掌控期间运行的回合仍会为你留下提案，但不会报告给协调者。

要让某个会话重新成为普通对话，在项目视图里选择**移出项目**。先决定它待处理的提案。

## 限制

- Wuu 必须在运行，会话才能工作。Wuu 关闭期间结束的回合，会在它再次启动后送达。
- 项目暂不支持定时器和外部触发。
- 每个会话各自发起模型请求，委派工作比单个对话消耗更多 token。
- 归档或删除项目会结束它的管理；它的会话保留为普通对话。
- 手机端直接打开项目的各个对话，不会把它们归组显示。

在单个对话里临时委派小任务，请使用[子代理](subagents.md)。
