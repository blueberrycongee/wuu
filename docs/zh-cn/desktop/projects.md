# 项目

Project Agent 尚属实验功能，发布构建中默认关闭，没有可供用户开启的设置。
已有项目会话仍可阅读，但不会运行或恢复排队任务。下文只适用于显式启用此功能的
构建，具体方式见[开发文档](../project/development.md)。

Project Agent 是与你对话的主 Agent：记住你的目标和决定，必要时直接动手，把独立工作交给它管理的会话。团队自己审查并交付工作：Agent 直接提交、合并、推送或开 PR，不需要等你审批。

项目协作是 Wuu 的内置能力。创建和管理会话、送达结果、人工接管以及重启恢复，都不需要安装或启用插件。扩展可以添加可选的工具，但不拥有项目及其会话。

## 开始一个项目

项目在侧栏顶部有自己的分组。在**项目**分组里选择 **+**，在当前工作区开始一个项目；或者在工作区的菜单里选择**新建项目**，在那个工作区开始。随后会打开一个项目草稿；选择**新对话**可以把它变回对话草稿。

告诉协调者你要的结果和约束：

```text
把目录搜索改成服务端分页，每页 50 条。
保持公开 API 不变。
```

发送第一条消息时项目才会创建，名称取自这条消息的第一行，之后可以像对话一样重命名。一个工作区可以有多个项目。

主 Agent 使用普通对话相同的工具和权限设置，遵守 `AGENTS.md` 等工作区指令（见[配置](../reference/configuration.md)）和技能。权限允许时，它可以直接修改当前工作区，改动立即生效。小任务不需要组建团队。

## 主 Agent、可选的 Side Agent 和 Worker

持续实现时，主 Agent 可以保留一个 **Side Agent**，再按需添加负责调研、实现或验证的 **Worker**。Side 也能创建 Worker，完成报告会同时送达分派它的 Side 和主 Agent；Worker 可以交流，但不能再创建项目会话。这些只是普通会话上的角色，复用历史、模型设置、工具、worktree 和用户控制。重复使用 Side 会保留上下文，重启后仍然如此。

主 Agent 分发目标、约束、负责范围、依赖和验收证据，把实现选择留给实际检查代码的 Agent；执行者可以质疑错误假设。成员看不到主 Agent 的对话，因此需要完整的任务说明和相关用户指令。主 Agent 仍负责检查、整合并验证最终结果。

成员可以直接给彼此或主 Agent 发消息。信息默认加入对方当前回合，或在对方空闲时等到下一轮处理，问题或行动请求可以明确唤醒对方。消息保留来源，重启后可恢复。重要决定应同步给主 Agent；其他 Agent 的消息不代表新增的用户授权。停止成员或给它发消息不会将其移出团队，也不会使排队中的团队消息失效。

新成员默认继承主 Agent 的模型，也可以选择已配置的模型别名。之后可以用普通对话的控件切换模型，不引入另一套模型或会话运行机制。

要把已有的工作带进项目，把对话从它的工作区拖到侧栏里的项目上。此后由协调者管理它，协调者会读到它最近的回答。只有同一个工作区的对话可以加入。

项目在侧栏里只占一行，它的会话不会挤进工作区列表。有会话在运行时，这一行会显示运行状态。在项目对话里：

- 输入框上方显示项目正在运行的工作，点击会在右栏打开项目，列出它的 Side Agent 和 Worker。运行指示表示执行状态，而不是项目成员关系。
- 每个事件（例如某个会话完成了一轮）在消息之间显示为居中的一行。点会话名打开该会话，**详情**显示协调者收到的原文。同一轮里连续的事件合并为一行并显示条数，展开后可以看到每一条。

在 Git 工作区中，会改动文件的会话默认在自己的 Git worktree 中工作，文件彼此隔离。worktree 不会解决接口冲突：重叠范围仍应只安排一个写入者，并一起验证改动。直接在工作区中工作的会话会原地修改文件。

会话的一个回合结束后，由协调者决定下一步：发出纠正、启动后续会话、交付改动，或者向你汇报。结果是证据，不代表目标已经达成。需要独立检查时，协调者可以让另一个会话审查某个会话的 worktree 或分支，运行测试而不修改这些工作。

## 交付改动

worktree 会话的改动留在它自己的分支上，直到团队交付。没有任何环节等你审批：由主 Agent 决定改动如何落地，例如提交并合并到工作区、推送分支或开 PR，再由某个会话用普通的 Git 和 `gh` 命令完成。这些命令和普通对话一样遵守项目的权限模式。想换一种交付方式，比如开草稿 PR 而不是直接合并，在项目对话里告诉主 Agent 即可。

## 给会话补充指令或停止会话

你随时可以给成员发消息。消息会补充到正在进行的回合，或开始新的一轮。成员仍属于项目，协调者会收到通知，但空闲时不会因此被唤醒。这一轮的结果也会包含你写的内容。

停止只会中断当前回合，不会转移控制权，也不需要交还。中断结果会送达协调者，但不会唤醒空闲的协调者。正常完成仍会唤醒协调者，停止的 worktree 回合的改动会留在 worktree 里。协调者之后仍可给同一个成员分配工作。

要让某个会话重新成为普通对话，在项目视图里选择**移出项目**。它的 worktree 和尚未交付的改动会留在这个对话里。

## 限制

- Wuu 必须在运行，会话才能工作。Wuu 关闭期间结束的回合，会在它再次启动后送达。
- 项目暂不支持定时器和外部触发。
- 每个会话各自发起模型请求，委派工作比单个对话消耗更多 token。
- 归档项目后，托管会话不会出现在桌面侧栏的普通对话列表中，重新加载后也一样。归档项目不会归档或停止这些会话；恢复项目后可在项目视图中访问它们。如果项目已被删除或不存在，保留下来的会话会显示在普通列表中，仍可访问。
- 手机端直接打开项目的各个对话，不会把它们归组显示。

在单个对话里临时委派小任务，请使用[子代理](subagents.md)。
