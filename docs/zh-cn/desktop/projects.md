# 项目

项目是一个与协调者的对话，用于在同一个工作区里推进较大的一块工作，例如一个功能、一次迁移或一轮清理。协调者负责规划，记住你的目标和决定，并把每一处改动交给它管理的会话去做。你审阅这些会话的产出，决定哪些进入工作区。

## 创建项目

在侧边栏打开工作区的菜单，选择**新建项目**，然后为它命名。一个工作区可以有多个项目；每个项目显示在所属工作区中，它的会话嵌套在它下面。

告诉协调者你要的结果和约束：

```text
把目录搜索改成服务端分页，每页 50 条。
保持公开 API 不变。
```

协调者会读取工作区，包括 `AGENTS.md` 等指令（见[配置](../reference/configuration.md)）和技能，但不能改动任何东西。它可以读取和搜索文件、运行只读命令、使用网络；不能编辑文件、运行会改动内容的命令，也不能操作浏览器。小而独立的任务用普通对话更快，也更省 token。

## 会话负责干活

协调者为每一块独立的工作启动一个托管会话，并为它写一份任务说明。会话看不到项目对话，只看到自己的任务说明和后续指令。每个会话都是普通对话，你随时可以打开。

在 Git 工作区中，会改动文件的会话默认在自己的 Git worktree 中工作，并行的会话不会互相覆盖。直接在工作区中工作的会话会原地修改文件。

会话的一个回合结束后，结果会出现在项目对话中，由协调者决定下一步：发出纠正、启动后续会话，或者告诉你哪些已经可以审阅。结果是证据，不代表目标已经达成。需要独立检查时，可以让协调者审查某个改动：它会从该改动的冻结副本启动一个单独的会话，审查可以运行测试，而不会修改这个改动。

## 审阅并应用改动

worktree 会话在一个回合结束时如果有改动，Wuu 会把它们冻结为一份改动提案。打开该会话即可查看改动的文件和 diff，然后选择其一：

- **应用到工作区**：只把这份改动写入工作区，不暂存。工作区有冲突改动时不会应用任何内容，提案保持待处理。
- **开 PR**：由扩展提供时出现，例如 [Git Delivery 示例](../../../examples/plugins/git-delivery/README.md)。
- **丢弃**：记录你拒绝了这份改动。

协调者会得知你的选择。worktree 会话的改动只有在你应用后才会进入工作区。

## 接管会话

在托管会话中发送消息即接管该会话：协调者不再向它发出指令，并会收到通知。中断会话会同样暂停管理。选择**交还给项目**即可交回，协调者会先检查改动再继续。你掌控期间运行的回合不会报告给协调者。

## 限制

- Wuu 必须在运行，会话才能工作。Wuu 关闭期间结束的回合，会在它再次启动后送达。
- 项目暂不支持定时器和外部触发。
- 每个会话各自发起模型请求，委派工作比单个对话消耗更多 token。
- 归档或删除项目会结束它的管理；它的会话保留为普通对话。

在单个对话里临时委派小任务，请使用[子代理](subagents.md)。
