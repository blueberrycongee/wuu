# Collaboration

Collaboration 是与具名 Agent 围绕项目持续工作的对话。Agent 负责读取、讨论和协调，普通执行会话负责实现。桌面和原生客户端隐藏群聊入口，已有群聊数据和协议方法保留。

## 开始项目对话

打开 **Collaboration** 并新建对话，选择已有 Agent，或创建新 Agent 并设置模型和名称。输入框上方的项目控件决定对话所属的已登记工作区，新 Agent 的第一段对话也会在这里打开。同一个 Agent 可以在不同项目里各有对话，导航名称和对话标题都会带上项目名。

说明结果和约束，例如：

```text
把 catalog 搜索改成服务端分页，每页 50 条。
保留公开 API，交付前让我看候选 diff。
```

对话绑定的项目是委派执行的默认目标。切换当前工作区不会改变已有任务的执行位置；项目不可用时会报错。旧的未绑定对话保留历史；需要明确项目路由时，新建绑定项目的对话。

协调者可以读取文件、讨论取舍、维护任务和管理会话，不能自行修改文件、执行命令或操作浏览器。只读判断可以直接完成，需要改动时使用执行会话。执行会话继承具名 Agent 的模型配置。

## 查看和控制执行

时间线中的任务卡显示状态、执行会话链接和取消入口。对话的会话面板可以打开任何托管执行。报告区分完成、失败和打断；一个回合结束不等于任务完成。

打开会话不会接管，向它发送消息才会暂停自动托管指令。点击 **交还托管** 后，Agent 可以检查你的改动再继续。对话输入框也可以打断协调者。

取消任务会停止关联执行及后续推进，不会撤销已执行的命令或文件改动。被暂扣的回复和已结束但未发布的回合会显示在对话中，便于判断为何没有回复。

任务保存带版本的目标、约束和决策。更新使用当前版本；目标或约束改变后，旧执行结果失效，相关回合被打断，原会话可接收修正指令继续。Git 并行实现默认使用独立 worktree，显式共享目录时一次只允许一个写入者。项目路由不是文件系统沙箱，执行仍遵守适用的[权限](../reference/permissions.md)。

## 审查候选

在任务卡展开 **审查候选**。候选包含冻结的 Git diff、执行结论、检查记录、未决问题和执行会话链接，实现中的取舍也会写入 Work。需要验证的任务会在冻结候选上启动独立的只读验证会话；缺少审查记录或结论不确定都不代表通过。

可以选择以下交付动作：

- **应用到项目**：应用已审查的补丁，不暂存。发生冲突时停止应用并保留已有改动；目标变化后需重新审查。
- **开 PR**：由已安装的 Git 交付扩展提供。可选的 [Git Delivery 示例](../../../examples/plugins/git-delivery/README.md) 只把候选补丁带入独立检出，创建 GitHub 草稿 PR。需要 Git、Node 和已登录的 `gh`；禁用扩展会移除该动作。Collaboration 核心不发布或合并 PR。
- **丢弃**：记录决定并保留执行历史。丢弃当前候选会使其验证失效，通知协调者重新判断。

检查记录是执行方提供的证据，不代表生产验收。交付前请检查 diff、命令和未决问题。没有 Git 改动的候选仍可阅读，但没有 Git 交付动作。

## 记忆与定时跟进

点击对话标题栏的 **记忆**，在侧栏中查看、编辑、新建或删除项目记忆与身份记忆。项目记忆由绑定同一工作区的对话共享，并自动注入协调和委派执行。身份记忆属于具名 Agent，跨项目有效。Work 决策提供任务上下文；执行会话能读取房间里的用户原话和自身历史，不能读取协调者私有 transcript 或尚未投递的私密消息。

在对话中让 Agent 安排一次或重复跟进即可。对话级定时任务不随原执行会话结束而消失。标题栏的 **定时任务** 显示进行中的数量，侧栏列出每项的下次时间，并支持暂停、恢复和取消。工作状态也有 host 管理的推进截止时间；停滞任务会进入可见的待处理状态，而不是一直等模型想起它。

执行任务和定时跟进都需要 host 运行。持久化安排不能让休眠或关机的电脑执行任务。

## 删除对话或 Agent

删除项目对话只移除该私聊，不删除具名 Agent。删除 Agent 会撤销凭据、移除其私聊和身份记忆、取消其负责或执行的未完成任务，并停止托管会话。已完成历史保留归属信息，普通执行历史和文件改动仍然存在；删除不会撤销已执行的命令。

仍由该 Agent 托管的会话（包括暂停中的会话）会移入**设置 → 归档 → Agent 归档**，不再出现在工作区导航、未读列表或普通归档中。你可以将它们恢复为独立会话。已经由你接管或解除托管的会话保持原状。旧版本删除 Agent 后遗留的托管会话也会补归入这个分区。

普通对话内的临时委派见[子 Agent](subagents.md)。开发者可查看[媒体交接契约](../automation/app-server.md#named-agent-media-handoff)。
