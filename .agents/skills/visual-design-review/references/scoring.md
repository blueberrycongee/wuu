# 布局协调分：实验性规则 v1

协调分是 0–100 的场景内迭代指标，不是通用审美定律。不需要假装它绝对准确，但必须固定提取方式、阈值、权重和条件，才能可靠解释变化。100 表示所选指标未超出容忍区间，不代表完美设计。

## 分项与误差来源

| 分项 | 初始权重 | 可选择的主要误差 |
| --- | --- | --- |
| 对齐 alignment | 25 | 锚点或可见中心相对目标的归一化偏离 |
| 间距 spacing | 25 | 同类间距偏离既定范围，或组内/组间关系偏离 |
| 重量 weight | 20 | 多尺度密度分区重量相对预期区间的偏离 |
| 留白 whitespace | 20 | 按用途划分的净空、空白占比或空洞尺寸超出区间 |
| 效果 effects | 10 | 阴影等效果相对同角色目标的方向、覆盖与干扰偏离 |

这些权重仅为初始假设。场景配置必须在测量前定义实际使用的指标、区域、目标、归一化分母与阈值。用相同角色、独立问题的少数指标，避免重复惩罚同一种质心偏移。允许自定义分项，但变更必须更新版本并重算基线。

所有送入评分器的 `error` 都是**非负、越小越好、已归一化的误差**，不是原始面积、质心坐标或模型自评。例：留白占比 `f` 的预期范围是 `[a,b]`，误差可取 `max(a-f,0,f-b)`，不能直接把占比当误差。需要定向或区间目标的指标由提取器先转换，评分器不会猜测。

归一化分母按语义预先固定：例如水平中心误差除以容器宽度，行距误差除以基准行距。分母为零、对象裁切、背景不可分离或提取不可靠时标记缺失，不编造数据。效果本身不存在与效果无法测量不同：经验证“无效果”为预期时误差可以为零，未能采集则必须缺失。

## 数学映射

对指标误差 `e`，配置免扣分阈值 `good>=0` 和饱和扣分阈值 `bad>good`：

`P(e)=clamp((e-good)/(bad-good),0,1)`

`S(e)=100*(1-P(e))`

同分项内按预先声明的指标权重平均，再按分项权重得到总分。单项不会扣成负数；严重裁切、遮挡、不可读或不可操作等约束独立报告，不能被平均分抵消。没有测过的约束为 `unknown`，不是 `pass`。

示例配置中的阈值只是为了演示接口，**不是已经验证的 UI 合格线**。场景首次校准要检查可接受和不可接受的代表样例，把阈值来源写在配置/提取器记录里。未校准时明确标注“实验配置”，不要默认 80 分合格。

## 缺项、不确定性与重复采集

每个指标必须提交同单位的误差上界 `uncertainty>=0` 和原始证据引用 `evidence`。无法估计误差界时不要填零：以 `null` 表示指标缺失，并在测量报告解释原因。零仅用于确实可以按当前数值模型无歧义计算的输入。

评分范围取 `[S(e+u), S(max(0,e-u))]`，按权重传播。它是保守的输入敏感性范围，不是置信区间。至少三次独立采集的总分取均值，范围取各次上下界的包络；同一截图不能复制成三次独立采集。工具只检查 capture ID 不重复，采集独立性由适配器保证。

覆盖率按固定分项与指标权重计算。任一规定指标在任一次采集中缺失时，对应分项及总分返回 `null`，仍展示其他完整分项与缺失清单；不删除难测指标后重新归一化成漂亮总分。运行覆盖率取各次采集的最低值。

约束检查与数值覆盖率分开。可以出现“分数完整，但约束未知/失败”，不能据此宣布可发布。一次采集可以给暂定分；不足三次时拒绝基线趋势判断。

## 可执行评分器

使用 Python 3 标准库，无网络、无图像库依赖。参考 [配置示例](../examples/profile.json) 与 [测量示例](../examples/measurements.json)。示例使用合成数据，只有一次采集且约束未知，故不能用于证明界面质量。

```sh
python3 "$SKILL_DIR/scripts/score.py" \
  --profile project-profile.json --input measurements.json > score.json

python3 "$SKILL_DIR/scripts/score.py" \
  --profile project-profile.json --input candidate-measurements.json \
  --baseline score.json > candidate-score.json

python3 -m unittest discover -s "$SKILL_DIR/tests" -p 'test_*.py'
```

`--baseline` 接收上次生成的完整评分报告。报告内保存配置和原始测量输入；比较时重新计算基线，忽略可被手动编辑的旧摘要。程序只向标准输出写 JSON，错误写到标准错误，输入无效返回 2；报告可正常生成返回 0。**返回 0 不表示视觉质量、覆盖率或约束通过**，调用者要检查报告字段。重定向时使用新文件名，不覆盖输入或基线。

测量输入含 `scene`、`scene_version`、`extractor_version`、`environment` 与 `samples`。环境至少描述视口、主题、UI/代码字体、缩放、平台、渲染器、语言、状态及内容版本，参见示例；未知环境不能伪装成已校准。每次 sample 包含独立 `capture_id`、指标字典和约束字典。遗漏或 `null` 指标算缺失；多余/错误 ID、负值、非有限值和无效阈值被拒绝。

报告包含指标分、分项分、总分及范围、覆盖率、约束状态和原始输入。展示给用户时分数通常保留一位小数，内部运算不提前取整。额外在测量产物中保留源图哈希、版本、提取脚本、ROI 与缺失原因；`evidence` 可以指向该记录，不要求分享实际截图。

## 基线比较与校准

评分配置的完整内容哈希、场景及版本、提取器版本、环境都相同，且两边覆盖完整并各有至少三次采集时，才计算差值。产品构建 ID 可放在输入额外字段中追溯，不放进需要完全相同的环境条件；比较的目的本来就是评价不同实现。字体或渲染环境变化则确实会破坏可比性。

总分差值范围为 `[candidate.low-baseline.high, candidate.high-baseline.low]`。包含零时输出 `inconclusive`；全正/全负只表示本规则下分数更高/更低，不表示人类偏好已验证。约束的前后状态一起显示，即使分数上升也不能掩盖新的交互问题。

不得自动用最高分结果替换基线。收集用户认可的成对样例，部分用于调参数，保留另一部分验证排序是否符合偏好。检查可读性、密度与风格的取舍，不针对单个截图调权重。修改规则后递增版本，用保存的原始证据重新提取/计算两版，而不是拿新规则分数和旧规则分数相减。
