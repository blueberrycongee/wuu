# 图片与 UI 布局测量协议

本协议规定可复查的测量方法，不是已经校准的人类视觉模型。包内评分器处理已提取的误差，不读取图片；精确像素数字仍须由图像工具产生。评分与多尺度分析分别遵循 [评分协议](scoring.md) 和 [空间分析](spatial-analysis.md)。

## 1. 输入、来源与坐标

保存用户提供的原图，不覆盖、不重采样。记录文件名、SHA-256、解码后的宽高、格式、色彩空间和已知的截图条件。优先使用原始无损截图；JPEG 和被聊天软件缩小的图片仍可分析，但压缩或缩放造成的轮廓误差必须保留。只有预览且拿不到原文件时，请求原图；可先给定性观察，不编造测量。

统一以解码后图像左上角为原点，x 向右、y 向下，单位为 `image px`。像素中心为 `(i+0.5, j+0.5)`，矩形用半开区间 `[x0,y0,x1,y1)`，宽高为 `x1-x0`、`y1-y0`。裁剪记录原图偏移；局部坐标必须能还原为原图坐标。应用 EXIF 方向等变换时保存变换关系，并以实际分析的像素方向为准。

只有已知截图与布局的映射时才额外报告 `CSS px`。例如：

`x_image = sx * x_css + ox`，`y_image = sy * y_css + oy`

记录比例与偏移的来源，并用同一平面上多个已知布局边界复核。浏览器缩放、设备倍率、截图裁剪、系统缩放和后期缩放都可能改变映射。不能只看图片 DPI 或 `devicePixelRatio` 就假定比例。DOM 坐标受滚动、iframe 和 transform 影响，须与截图视口对应。

若未知比例，报告图片像素及相对容器尺寸即可。显示器照片或有透视的素材不能直接用于原 UI 的像素测量；有可靠控制点时可校正，但要报告校正后的估计误差。放大和超分辨率不会恢复测量真值。

## 2. 先确定测量对象

为每个区域分配 ID，并记录原图 ROI、父区域、同级组、元素角色与预期关系。预期关系来自组件契约、设计系统、同级结构或用户意图，不由指标自行决定。无法确认时并列报告事实与假设。

区分三种边界：

- **布局框**：DOM 或其他布局采集数据中的边界；包含内部空白，不代表可见墨迹。
- **可见轮廓**：图片中经确认的目标内容，包括字形、笔画；不自动包含阴影、外发光、焦点环。
- **感知代理**：在指定区域、背景与权重定义下计算出的质心或重量分布。

截图不能可靠揭示隐藏点击区域、文字真实基线、字体 ascent/descent 或容器不可见的 padding。OCR 框适合找文字，不可自动当作精确字形框或基线。需要精确基线时获取布局与字体数据，否则只报告可见字形的上下边界。

先检查单个控件内的关系，再检查同级元素和面板。没有设计上的对称要求，不判定全屏质心偏离中心就是缺陷；主操作有意更突出也不是异常。

## 3. 提取可见内容

先裁剪目标，再选适合该素材的方法。记录库版本、执行命令、背景取样区域、色彩转换、阈值、连通域选择及排除区域。不能仅凭肉眼在预览图中猜边界后宣称像素级检测。

透明素材可用 alpha 定位轮廓，但视觉重量仍依赖实际背景；已知背景时先合成再测对比。均匀背景可用周围未受目标影响区域的颜色中位数估计背景，并检查背景变化。渐变、纹理或照片背景优先使用目标掩膜、背景参考图或人工确认的分割；缺少可靠分离条件时停止精确轮廓判断。

抗锯齿边缘不是二值真值。使用覆盖合理范围的至少三个阈值复算边界与质心，报告变化范围与阈值单位；不要挑选支持预想结论的单个阈值。阴影、边框、状态点、文字及图标应按问题分别测量，避免把邻近像素误合并为同一个对象。若做去噪或形态学处理，保留原始掩膜与处理后掩膜并说明边界变化。

将掩膜和边界叠加在原图上检查是否包含目标、是否误选邻居、是否截断。工具无法查看图像时，只能称为未目视确认的计算结果。空掩膜、零总权重、被裁切对象、重叠且无法分割的对象均报告不可测原因，不填零。

## 4. 几何指标

所有指标都绑定区域、参照和单位；选择与问题有关的指标，不为了填表计算无关分数。

### 对齐

对同级元素的同一种锚点 `a_i`（左边缘、右边缘、中心线或已知基线），优先使用已知目标锚点 `a*`：

`e_i = a_i - a*`

没有指定目标时可取该组锚点中位数作为描述性参照，同时报告 `max(a_i)-min(a_i)`。中位数只能发现相对偏差，不能证明整组位置正确。不同层级、不同缩进、换行与不同状态的元素不可无条件混为一组。

### 可见留白与居中

容器边界为 `[L,T,R,B)`，内容边界为 `[l,t,r,b)`：

`g_left=l-L`，`g_right=R-r`，`g_top=t-T`，`g_bottom=B-b`

`d_x=((l+r)-(L+R))/2=(g_left-g_right)/2`

`d_y=((t+b)-(T+B))/2=(g_top-g_bottom)/2`

正值表示内容几何中心向右或向下偏。额外报告 `d_x/(R-L)` 与 `d_y/(B-T)` 便于跨尺寸比较；分母必须非零。负留白表示内容越界，不能截断成零。这里测的是可见内容到已知边界的距离，不自动等于 CSS padding。

### 间距节奏与分组

同一行内、按 x 排序的元素间距为 `g_i=left_(i+1)-right_i`；列方向同理。负值表示包围盒重叠，仍需检查真实轮廓。换行按行分别测量。

按语义分别统计行间、标题到内容、内容到操作、组间距离。报告样本数、各原始间距、中位数、范围与 `MAD=median(|g_i-median(g)|)`。MAD 为零时仍保留非零偏差，不进行除零或忽略异常。样本太少时只描述差异，不声称有统计显著性。

组内与组间距离可用中位数比值辅助观察，仅在组内距离为正且分组明确时计算。没有通用的最佳比值；边界、颜色与对齐也影响分组。比较同类关系和已有设计 token，不强迫所有留白相等。

## 5. 感知代理指标

使用明确、可重复的对比度模型。可以将它纳入版本化的实验性协调分，但必须公开权重与适用范围，不把面积、饱和度、语义重要性随意加权成“科学总分”。

对标准 sRGB 素材，将归一化通道值 `c` 转为线性值：当 `c<=0.04045` 时为 `c/12.92`，否则为 `((c+0.055)/1.055)^2.4`。线性亮度 `Y=0.2126R+0.7152G+0.0722B`。其他色彩空间先进行明确的色彩管理转换；未知时说明假设。透明像素先与已知背景合成，不能把隐藏 RGB 直接计入重量。

在确认的目标掩膜内，取 `w_p=|Y_p-Y_bg,p|`，掩膜外取零。像素权重属于对比度代理，等亮异色的内容可能被低估；遇到这种情况说明模型不适用，不能解释成“没有视觉重量”。

`M=sum(w_p)`

`cx=sum(w_p*x_p)/M`，`cy=sum(w_p*y_p)/M`

只有 `M>0` 才计算。相对指定目标中心 `(tx,ty)` 报告 `cx-tx`、`cy-ty` 及除以容器宽高后的偏移。这是**对比度加权质心**，不是眼动注意力中心，也不是通用的光学居中答案。

确实需要分析左右视觉重量时，在同一语义区域与参照轴 `tx` 下分别计算：

`T_left=sum(w_p*max(tx-x_p,0))`

`T_right=sum(w_p*max(x_p-tx,0))`

`A_x=(T_right-T_left)/(T_right+T_left)`

分母为零时不可测；上下方向同理。这个归一化力矩差包含距离因素，只描述该模型下的分布，不要求结果为零。不要把质心偏移和力矩差当成两份独立的验证证据。复杂页面、文字密度、语义和颜色显著性仍需单独解释。

## 6. 精度、误差与判断

区分计算值、分割误差与模型局限。质心能算出小数，不代表知道原布局的亚像素位置。最终展示位数不得超过输入和识别可靠性；机器可读数据可保留计算精度并附误差范围。

若两个边界的定位误差上界分别为 `u1,u2`，距离的保守误差上界为 `u1+u2`；多阈值结果的最小/最大值是敏感性范围，不冒充统计置信区间。CSS 换算还须考虑比例与偏移的校准误差。无法量化的误差明确写未知，不虚构置信百分比。

判定依次考虑：是否违反已知关系；差异是否超过测量不确定性；是否在实际使用尺寸可辨认；是否影响阅读、交互或层级。固定“超过 1 px 就不平衡”不适用于所有字号、倍率和组件。没有预期关系或感知验证时，标记“差异”或“候选问题”，而不是直接判错。

修改建议从最小候选开始，不直接把质心偏移取反用于代码。前后采集条件、分割规则、阈值与指标保持一致；若必须改变规则，对两版同时重新计算。隐藏辅助线后再比较，避免标注诱导观感。

## 7. 可复查交付

每次测量保存原图引用、可复运行的计算脚本或命令、数据 JSON 和标注图。输出到任务专属的可写产物目录，不修改原图，不默认把用户截图提交到仓库。标注使用独立图层或副本；放大细节仅供检查，必须注明缩放倍率。

JSON 至少包含以下字段，未知值使用 `null` 并说明原因，不填示例数值：

- `source`：文件路径、SHA-256、原图尺寸、格式、色彩空间。
- `capture`：已知主题、字号、视口、状态与缩放信息。
- `coordinates`：原点、单位、裁剪偏移、可选 CSS 映射及校准来源。
- `regions`：区域 ID、ROI、角色、父组、参照、边界来源、掩膜与算法参数。
- `measurements`：区域 ID、指标、数值或不可测原因、单位、误差或敏感性范围。
- `findings`：事实、解释、建议、验证状态分别记录；注明结论依赖哪些测量。
- `artifacts`：标注图、掩膜、脚本或命令记录的位置与工具版本。

标注图显示区域 ID、容器和可见边界、参照线、几何中心、可选加权质心及距离箭头；只显示当前结论需要的标记，避免遮住证据。涉及不同单位时分开标注。

给用户先说明最重要的发现，随后用测量表提供位置、指标、值与误差、参照和结论类型。明确哪些来自几何实测、哪些来自感知代理、哪些仍待目视确认。不能用“总分提升”替代具体变化，也不能把合成图片的结果声称为真实软件验证。
