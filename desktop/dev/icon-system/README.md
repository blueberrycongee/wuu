# Icon-system review surface

The complete family is integrated into `desktop/src/shared/iconArtwork.ts`, the
single artwork source used by React controls and main-process HTML. All 148 names
are retained; 147 drawings change and Project preserves its distinctive mark.
The comparison keeps the pinned baseline and exports the updated column from
production, so it cannot drift into a separate candidate implementation.

## Preview

From the repository root, run:

```sh
node desktop/dev/icon-system/build-preview.mjs
python3 -m http.server 5178 --bind 127.0.0.1 --directory desktop/dev/icon-system
```

Open `http://127.0.0.1:5178`. Compare the current snapshot and proposed SVGs at
14, 15, 16, 20, 24, or 48 CSS pixels, in light and dark themes. The control switch
exposes 28px inline, glyph-plus-12px toolbar, and 44px touch specimen boxes.
Hover, keyboard focus and disabled presentation are available in the specimen;
these are not end-to-end product interaction tests.

The baseline snapshot is from `7dfe8f99fc4592324aa4015ba2224652765dc00b`.
The candidate is original vector artwork, authored directly as paths. No
external product-control paths or generated raster tracing are used.

## Drawing rules

- Keep the existing 24-unit grid and 1.75 stroke, with rounded caps and joins.
- Use straighter runs with curved shoulders, usually a 3-unit outer corner.
  Avoid turning every enclosure into a pill or filling its interior.
- Fit typical containers in a 16–17-unit body. Circular, branching and diagonal
  glyphs have optical allowances rather than a blanket scale transform.
- Keep inner counters open. Shorten crowded details and favor one clear symbol
  over an extra badge. Sparse symbols can be smaller than complex containers.
- Reserve filled shapes for dots and playback. Pins, sliders, terminal strokes
  and energy marks use the same outline weight as adjacent controls.
- Keep familiar direction/action semantics and Wuu-specific identity. Bot stays
  a ball with two capsule eyes. Project retains its existing distinctive mark
  unchanged. Message tails and panel partitions stay explicit.
- Wuu's application icon is outside this change and remains unchanged.
  Third-party provider, engine and GitHub identities remain their own marks.

## Source coverage

`icon-groups.mjs` contains the full six-group catalog. The groups contain
35 navigation/layout, 25 editing/action, 14 message/people, 36 tool/workspace,
15 file/content and 23 status/feedback names. Aliases retain named entries.

The generator scans `desktop/src`, `clients`, and `plugins` for named imports,
JSX sizes, dynamic references and inline SVG. At the pinned baseline there are
90 WuuIcons import files and 410 direct JSX calls. The generated local inventory
contains exact source paths, lines and literal attributes. CSS and dynamic
component maps can override those values; this is not a runtime size census.

Additional sources and integration boundaries:

- `WuuIcons.tsx` owns SVG/accessibility props and exports; `iconSVG` serves
  main-process activity-PiP and cursor consumers. Keep one artwork source.
- `PublicIcon` maps 29 extension-facing names; `PluginBlocksIcon`,
  `SidePanelToggleIcon`, and `CapabilityMark` reuse the same controls.
- `codexPetWindow.ts` contains 12 separate 16-grid controls. The local inventory
  records their proposed mapping to shared semantic icons. Preserve each
  window's existing dimensions and labels when adopting the family.
- iOS snapshots `WuuCopy`, `WuuSplit` and `WuuCheck` are generated by
  `clients/native/shared-ui/export-icons.mjs`, not independently redrawn.
- `ComposerContextMeter`, `ComposerTokenGauge`, todo progress and desktop-update
  rings encode changing values. Their geometry, dash animation and state color
  require a separate functional review; they must not become decorative icons.
  The todo completion mark can share the approved check geometry.
- Twelve Morandi SVGs are referenced by the development icon gallery and docs,
  not the active product renderer. They are illustration assets, not control
  replacements.
- Provider/engine marks, user/plugin-supplied SVG, rendered content, cursors,
  mascot animation, onboarding illustration and the wordmark have separate
  ownership and rendering contracts. Do not bulk-replace them via this catalog.
- The 148-name catalog includes currently indirect or unused exports so that
  new call sites cannot fall back to the previous family accidentally.

Current role sizing lives in `appearance.css`, `base.css` and `icon-controls.css`.
Most direct uses are CSS-sized. Explicit JSX sizes include 12, 14, 15, 16, 17,
18, 20, 22, 24, 28 and 32. Main-process uses include 16, 28 and 34. The 14/15/16/20
review sizes deliberately cover small controls and enlarged UI settings.
No production CSS, labels, handlers, hit areas or layout are changed here.

## Regeneration

With the desktop dependencies installed and Node 24 (or Node 22 with built-in
TypeScript stripping enabled):

```sh
node desktop/dev/icon-system/build-preview.mjs
```

This validates catalog coverage and writes `production-artwork.json`, the SVG atlases and a local source
inventory. The current snapshot is retained, not silently replaced on each run.
To render the atlases with Inkscape:

```sh
for file in desktop/dev/icon-system/rendered/*.svg; do
  inkscape "$file" --export-type=png --export-filename="${file%.svg}.png"
done
```

The PNGs are direct SVG rasterizations. They are design specimens, not
screenshots of the application, and contain no edited application captures.
Review at 100% for native pixel-size judgments; the 3× detail is labeled.
A successful catalog render does not replace live desktop visual acceptance.
